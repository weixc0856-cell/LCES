## 7. 根因

1. **源文本的数学/表格表示不适合自由文本引用。** HTML 抽取保留了下标展开、零宽字符、重复的 LaTeX 残片和表格行拼接；模型再改写成可读公式，字符串定位必然失败。
2. **模型不擅长报区块 ID。** 它倾向报章节，或报同节中错误的区块；定位器拒绝跨区块搜索是正确的，但产出率因此下降。
3. **候选生成仍以“改写后引用”为主。** 模型能写出正确的 claim，却很少复制连续原文，尤其公式和表格。
4. **trial 的窗口拆分**：A/B 各被章节规则拆成 2 个窗口；这不影响四个小节的覆盖，但不是严格的“两次调用”设计。脚本已改为每组一个窗口，并在输出目录保存 SourceMap 与源文本快照，便于复现。

## 8. 下一步（按评审文档的 C 分支）

定位器仍大量失败，先修源文本结构、区块归属和证据类型，不切换云端模型：

1. **章节级区块解析**：候选可以只给 section；定位器在该 section 的所有区块中搜索，只有引文完整落在**单一区块**内才接受，并记录实际 `chunk_id`。这能修复 B2-003 类型的错误归属，仍禁止跨区块拼接。
2. **区分证据类型**：公式/表格不再要求自由文本逐字引用，改为结构化证据（公式编号、表格编号 + 行标签 + 数值），由程序核验数值和变体；散文摘要才使用 `quote` 定位。
3. **表格/公式解析**：评估结构化表格提取（HTML table / PDF 表格）和公式文本规范化；在源文本能稳定表示之前，不把表格行当作 quote。
4. **提示词约束**：散文证据只引用连续句子；公式/表格证据填写结构化 locator；不得用 `•`、省略号或表格拼接。
5. **重跑两窗口验证**：使用修复后的脚本（每组一个窗口 + 源快照），目标：散文候选定位率显著提升，0 跨区块，关键公式/表格 claim 有结构化证据或明确 `needs_review`。

在这些完成前，不进入 P0-B3 的单元生成，也不冻结 `CourseMaster` / `UnitDraft`。

## 9. 阶段 A：章节级解析与原候选重验

按评审决定，先只加章节级解析，用同一批 18 条候选重验，不调用模型。

实现：

- 候选可提供 `section_id`，或把章节写在 `locator`（`§3.2.1 ...`）。
- 定位器只在该章节的区块中搜索；引文必须完整落在**单一区块**内才接受。
- 接受时记录实际 `chunk_id` 与 `resolved=True`；找不到或同节多个区块都匹配时为
  `needs_review`（`not_found_in_section` / `ambiguous_section`）。
- 仍禁止跨区块拼接；数学/表格差异仍不通过。

结果（`var/quote-locator-retrial/report.md`）：

| 状态 | 重验前 | 重验后 |
|---|---|---|
| verified_exact | 6 | **7** |
| verified_normalized | 0 | 0 |
| needs_review | 12 | 11 |
| rejected | 0 | 0 |

- 章节级解析解决了 **1 条**：B2 `evidence-003` 的句子在 `b0053`，模型声明 `b0052`；
  重验后接受，实际区块记录为 `b0053`，`resolved=True`。
- 没有新的错误通过：7 条 exact 中 6 条与重验前相同，另 1 条为上述区块归属修复。
- 其余 11 条仍为 `needs_review`：5 条数学/公式、4 条表格、1 条列表拼接、1 条源文本重复；
  另有一些是**章节归属错误**（如 A2 `evidence-003` 声明 §3.2.2，原文在 §3.2.3），
  章节级解析不能修复，仍应明确待复核。
- 结论：章节级解析的收益与预期一致（+1，6/18 → 7/18），它解决“区块报错”而不是
  “章节报错”，也不能解决公式/表格的源文本表示问题。
