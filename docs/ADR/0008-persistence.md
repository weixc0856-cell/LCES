# ADR 0008: 数据持久化复用 JSON 与 SQLite

对应 SAD-001 §12 ADR-006。状态：Accepted。

## 背景

课程工作区天然是文件系统：`content/`、`internal/`、`build/`、`release/` 需要能被
人工审阅、Git 追踪（除工作区数据外）和离线打包。跨项目状态（任务、阶段运行、
资产、审批）适合 SQLite。两者已经分别在用。

## 备选方案

1. 全量数据库（课程正文也入库）：破坏可审阅性与公开/内部文件边界，且让
   离线发布包难以自描述。
2. 全量文件 + JSON 索引：任务并发与查询会退化为全目录扫描。
3. JSON 契约 + SQLite 运行记录（当前）。

## 决定

- 课程事实、证据、审核记录、构建产物：项目目录内的 JSON/CSV/HTML，原子写入。
- 运行状态、阶段记录、资产登记、审批：`var/lces.sqlite3`（路径可配置）。
- 任何新持久化都必须回答：谁是唯一写入方、如何原子写、如何验证哈希、
  离线包是否需要它。

## 后果

- 正面：课程包可独立审阅；数据库损坏不影响已发布的课程事实。
- 负面：没有 schema 迁移框架；SQLite 结构变更需要兼容旧库。
- 监测点：出现跨项目查询或多人并发写入时，评估迁移工具。

## 证据

`storage.py`、`paths.py`、`utils.write_json_atomic/write_text_atomic`；
`tests/test_storage.py`、`tests/test_p23_filesystem_boundaries.py`（原子写与符号链接边界）。

## 回滚

数据库可以删除重建（运行历史丢失）；课程目录不可由数据库重建，因此不得反向迁移。
